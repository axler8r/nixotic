# Installing Nixotic
Covers fresh-machine installation, first-boot setup, ZFS disk layout, and
ongoing ZFS operations for `ambul8r`.


## Fresh Install
The installer partitions the disk, creates the ZFS pool via disko, generates
`hardware-configuration.nix`, patches `boot.resumeDevice`, and runs
`nixos-install` — all in one step.

**From the published flake** (no local clone needed; uses the last-committed revision):
```bash
sudo nix run github:axler8r/nixotic#install -- ambul8r
```

**From a local checkout** (all changes must be committed; uncommitted edits are
invisible to Nix):
```bash
sudo nix run .#install -- ambul8r
```

`nixos-install` prompts for a root password partway through. Reboot when done.

> [!NOTE]
> If the installer environment does not have flakes enabled globally, enable
> them for the duration of the install:
> ```bash
> export NIX_CONFIG="experimental-features = nix-command flakes"
> sudo -E nix run github:axler8r/nixotic#install -- ambul8r
> ```


## After First Boot
The installer clone at `/tmp/nixotic` is gone after reboot. Two files must be
persisted before the first rebuild — they contain hardware-specific values
generated at install time that the flake cannot know in advance.

### 1. Clone the Repository
```bash
git clone https://github.com/axler8r/nixotic.git ~/.nixotic
```

### 2. Persist Hardware Configuration
`hardware-configuration.nix` is generated by probing hardware — kernel modules,
detected filesystems, CPU topology. It is machine-specific and gitignored; the
repo holds a placeholder. Copy the real one from `/etc/nixos/`:

```bash
sudo cp /etc/nixos/hardware-configuration.nix \
    ~/.nixotic/hosts/ambul8r/hardware-configuration.nix
```

### 3. Persist the Swap UUID
`boot.resumeDevice` must reference the swap partition by UUID, not device path,
because device paths like `/dev/nvme0n1p3` can shift between boots. The UUID is
assigned by `mkswap` at install time; the repo holds a placeholder — replace it
with the live value:

```bash
SWAP_UUID="$(blkid -t TYPE=swap -o value -s UUID | head -1)"
if [[ -z "${SWAP_UUID}" ]]; then
  echo "No swap UUID found; update boot.resumeDevice manually."
else
  sed -i \
    "s|boot\.resumeDevice = \"/dev/disk/by-uuid/[^\"]*\"|boot.resumeDevice = \"/dev/disk/by-uuid/${SWAP_UUID}\"|" \
    ~/.nixotic/hosts/ambul8r/configuration.nix
fi
grep 'boot.resumeDevice' ~/.nixotic/hosts/ambul8r/configuration.nix
```

### 4. First Rebuild
Commit both files, then apply:

```bash
cd ~/.nixotic
sudo nixos-rebuild switch --flake .#ambul8r
```

This is the only time `nixos-rebuild` is used directly. For all subsequent
updates, use `nh` — it shows a diff of added/removed packages and provides
cleaner progress output:

```bash
nh os switch
```

See [`docs/validation.md`](validation.md) for the full validation pipeline
before applying changes.


## Disk Layout
The authoritative declaration is [`hosts/ambul8r/disk.nix`](../hosts/ambul8r/disk.nix).

| Partition |  Size | Type | Purpose     |
| --------- | ----: | ---- | ----------- |
| nvme0n1p1 |    5G | vfat | /boot (EFI) |
| nvme0n1p2 |  150G | ext4 | / (root)    |
| nvme0n1p3 |   32G | swap | Hibernation |
| nvme0n1p4 | ~766G | ZFS  | dpool       |

Root and boot stay on ext4 so the ZFS pool can be wiped or transplanted to
another machine without destroying the OS.


## ZFS Pool Structure
The pool is split into `HOSTDATA` and `USERDATA` so that a machine rebuild —
which wipes root — does not touch personal data. `USERDATA` datasets mount
directly into the home directory and survive reinstalls.

```
dpool                                    mountpoint=none
├── HOSTDATA                             mountpoint=none
│   └── var/lib/docker                   /var/lib/docker
└── USERDATA                             mountpoint=none
    └── home/axl                         mountpoint=none
        ├── Documents                    /home/axl/Documents
        ├── Downloads                    /home/axl/Downloads
        ├── Media                        /home/axl/Media
        ├── Projects                     /home/axl/Projects
        │   ├── AxlER8R                  /home/axl/Projects/AxlER8R
        │   ├── GitHub                   /home/axl/Projects/GitHub
        │   ├── GitLab                   /home/axl/Projects/GitLab
        │   └── Sandbox                  /home/axl/Projects/Sandbox
        └── Vaults                       /home/axl/Vaults
```

`Projects/` subdirectories are separate datasets so each can have its own
snapshot schedule and quotas independently.

Dataset ownership is set by `systemd.tmpfiles.rules` in
`hosts/ambul8r/configuration.nix`, which runs on every boot.


## Required NixOS Configuration
```nix
boot.supportedFilesystems = [ "zfs" "nfs" ];
boot.zfs.forceImportRoot = false;
boot.zfs.extraPools = [ "dpool" ];

# ZFS refuses to import a pool that was last used by a different machine.
# hostId is how it detects this. Derive with: head -c 8 /etc/machine-id
networking.hostId = "001421c4";

# Hibernate target (UUID generated at install time — see "After First Boot").
boot.resumeDevice = "/dev/disk/by-uuid/<swap-uuid>";

services.zfs = {
  autoScrub.enable = true;
  autoScrub.interval = "monthly";
  trim.enable = true;
};
```


## ZFS Operations
### Common Commands
| Command                                              | Purpose                 |
| ---------------------------------------------------- | ----------------------- |
| `zpool status`                                       | Check pool health       |
| `zpool scrub dpool`                                  | Manual scrub            |
| `zfs list`                                           | List datasets and usage |
| `zfs list -t snapshot`                               | List snapshots          |
| `zfs snapshot dpool/USERDATA/home/axl/Projects@name` | Create snapshot         |
| `zfs rollback dpool/USERDATA/home/axl/Projects@name` | Restore snapshot        |
| `zfs destroy dpool/path@snapshot`                    | Delete snapshot         |
| `systemctl hibernate`                                | Hibernate laptop        |


### Adding New Datasets
Edit `hosts/ambul8r/disk.nix` to add the dataset — disko creates it on the
next fresh install. To add a dataset on a running system without reinstalling:

```bash
# Inherits mountpoint from parent (e.g., a new project under Projects/)
sudo zfs create dpool/USERDATA/home/axl/Projects/NewProject
sudo chown axl:users /home/axl/Projects/NewProject

# Top-level dataset with an explicit mountpoint
sudo zfs create -o mountpoint=/home/axl/NewFolder dpool/USERDATA/home/axl/NewFolder
sudo chown axl:users /home/axl/NewFolder
```

Then add the corresponding entry to `disk.nix` and `systemd.tmpfiles.rules`
to keep the declaration in sync with reality.


### Dataset Recovery
If datasets are accidentally destroyed, use
[`files/zsh/functions/New-ZfsLayout`](../files/zsh/functions/New-ZfsLayout)
to recreate them without a full reinstall:

```bash
sudo New-ZfsLayout    # recreates missing datasets, skips existing ones
```
